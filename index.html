Appendices A–F — integrated controls

These are operational mechanisms used by the 30-stage workflow when applicable, not additional stages and not a duplicate checklist workflow.

A — Fresh agent context launch

Creates and validates fresh independent execution/review contexts, frozen inputs, tool configuration, contamination status, output identity, and run usability.

B — Universal blocker

Creates a blocker when a mandatory fact cannot be established, records affected requirements and resolution attempts, and stops affected downstream work until evidence resolves it.

C — Change and invalidation

Records material changes append-only, creates new artifact versions, invalidates dependent determinations, and requires every affected test, iteration, audit, gate, and hash check to be rerun.

D — Exact final release

Authorizes only an ACCEPTED product whose mandatory evidence, tests, audits, evidence chains, and immediate pre-delivery SHA-256 identities satisfy the release controls.

E — New-job reset

Creates a clean Stage 01 job state and prevents old requirements, tests, evidence, baselines, defect dispositions, and release decisions from carrying into a new job without explicit reuse authority.

F — Universal agent-output receipt

Captures every agent response or artifact immediately with context, input versions, output identity, hashes, truncation/refusal/tool/attachment failures, deviations, defects, blockers, and the next independent verification stage.
