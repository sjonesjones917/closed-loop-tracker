# Closed-Loop Reliability — hosted iPhone build

This repository publishes the phone-first Closed-Loop Agent Reliability workflow as a normal HTTPS web application for Safari/iPhone. Do **not** open the repository's HTML as an iOS local-file preview; iOS file preview may display the markup without executing the application JavaScript. Use the GitHub Pages URL instead:

https://sjonesjones917.github.io/closed-loop-tracker/

## Current deployed application identity

The Pages build reconstructs the exact audited application from `payload/v8-part-00.txt` through `payload/v8-part-07.txt`, then verifies it before deployment.

- Application byte size: 435,547 bytes

- Workflow operations: 30
- Included real-job project: `REAL E2E JOB — Inventory Reconciliation`

`tools/build-pages.py` fails the deployment if the reconstructed bytes, size, SHA-256, or required application markers do not match. It writes the verified application to both `dist/index.html` and `dist/404.html`, then the GitHub Pages workflow deploys only `dist`.

## App behavior

- Projects are persistent in browser-local storage and can be backed up.
- IDs are generated by the application where the workflow requires them.
- Stage progression is gated by the required response/evidence fields rather than a bare completion counter.
- Ten-run execution operations require their run records; verification operations require verifier records.
- Upstream material changes invalidate affected downstream state and require a new version.
- The included real-job project exercises a failure, root-cause/correction cycle, corrected ten-run batch, unchanged confirmation batch, baseline, finished artifact, verification, release gate, and release hash.
- The application is designed for narrow phone widths and avoids a fixed desktop canvas.

## Deployment

`.github/workflows/pages.yml` runs on every push to `main`. It reconstructs and verifies the exact application with `tools/build-pages.py` and deploys the resulting `dist` directory to GitHub Pages.
