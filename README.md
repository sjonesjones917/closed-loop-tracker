# Closed-Loop Reliability

Live application: https://sjonesjones917.github.io/closed-loop-tracker/

This repository contains one application with one HTML entry point: `index.html`.

The application is a phone-first human project interface over the exact 30-stage Mobile Closed-Loop Agent Reliability Workbook. The stages remain Stage 01 through Stage 30; no additional workflow operation is inserted and no supplied stage is removed.

The closed loop is: initialize the job → inventory every governing source → research requirements → compile atomic requirements → resolve requirement defects → build verification before production instructions → build failure tests → author and independently preflight the instruction → freeze the candidate → run ten independent executions → independently verify and compare them → root-cause defects → preserve regression tests → revise the responsible layer → run a new complete ten-execution iteration → establish convergence → run an unchanged ten-execution confirmation → freeze the production baseline → generate the finished product → run deterministic, independent semantic, adversarial, and final-representation verification → reconcile process and product evidence → apply the release gate → verify release-byte identity → preserve complete evidence chains → preserve defects and regressions permanently.

`human-ui.js` turns the workbook controls into project forms, contextual actions, project history, evidence views, blocking behavior, version/invalidation controls, file identities, release readiness, and stage gates rather than reproducing the workbook as a permanent wall of checkboxes.

Appendices A-F are cross-cutting application behavior: actual fresh-context evidence and isolation records; reusable blockers that stop affected downstream completion; controlled changes that invalidate downstream determinations; final-release readiness derived from project state; clean new-project initialization; and complete generated-output receipts. Appendix behavior appears where it is relevant to the project rather than as six disconnected checklist pages.

`TEST_PROJECT.json` is a real retained job: a maintenance handoff for generator `GEN-042` from supplied telemetry and an output contract. `build-test-project.mjs` deterministically expands that source seed into the fully populated retained project used in deployment verification. The retained project uses the same `human-project/30` model and the same views and controls as ordinary projects. It preserves source records, requirements, validators, two ten-run iterations, an initial defect and root cause, permanent regression evidence, corrected reruns, convergence, unchanged confirmation, baseline, finished product, product audits, release decision, hash identity, evidence chains, and the Stage 30 permanent registry.

Generated instructions are visible inside their stage. Their identity is tied to the current controlled input/source/requirement/test/instruction/iteration/baseline signature. A material version change makes downstream generated instructions stale instead of silently continuing to present them as current. Independent-run packages exclude other run outputs, reviewer comments, failure explanations, and proposed corrections.

Input and product files can be attached through the project workflow and receive browser-calculated SHA-256 and byte-size identities. Project JSON import validates the application schema, stage range, requirement/test identifier uniqueness, and test-to-requirement mappings before accepting the project.

`node verify.mjs` checks the exact 30-stage architecture, single-app structure, real retained project, ten-run isolation records, verification matrices, root-cause/regression loop, convergence, confirmation, immutable baseline, finished-product verification, Stage 26 reconciliation, release gate, byte identity, complete evidence chains, and permanent registry.

The GitHub Pages workflow builds the same real retained project for source verification, deployment, and live identity checking. It then renders the deployed application at an actual 320 CSS-pixel viewport and verifies the 30-stage workflow, compact human controls, project history, and clean New Project reset.
