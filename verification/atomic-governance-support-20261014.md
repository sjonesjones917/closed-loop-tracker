## Active atomic contract

`requirement-evidence-bindings.json.atomicExtraction` optionally supplies the agreed `draft`, `independentReview`, `reconciliation` file descriptors (`path`, raw file `sha256`, `actorId`, `contextId`, `specificationSha256`), plus `status`. The reviewer descriptor has `draftManifestReceived:false`. Only `RECONCILED` activates replacement entries; missing or `PENDING` stays blocked. Actors and contexts are distinct. All evidence is repository-relative JSON under `verification/` or `specification/`.

Draft and blind review records use `closed-loop-atomic-extraction-evidence/1`, `role:DRAFT|INDEPENDENT_REVIEW`, matching actor/context/source identity, `complete:true`, exact declared `inputs`, `propositions`, and complete ordered `sections`. The review has `draftManifestReceived:false` and only the source input. Each proposition has `propositionId`, `statement`, `primarySourceLine`, raw `sourceLineSha256`, and exact `contextSourceLocations`. Each section uses the mechanical heading inventory's exact `sectionId/startLine/endLine`, `disposition:COVERED|NONNORMATIVE`, `propositionIds`, and reason. Preamble propositions remain source anchored outside heading ranges. Structural/historical context propositions in both passes must explicitly provide the matching `classification` and reason.

Reconciliation uses `closed-loop-atomic-reconciliation/1`, matching identity, `complete:true`, `status:RECONCILED`, `inputs`, `priorManifest:{path,sha256}`, `entries`, `requirementIdentityCrosswalk`, `decisions`, `unresolvedMaterialDisagreements:[]`, and complete `sections` using `normativeRequirementIds`. It must resolve every proposition exactly once and map every active entry. Each decision has `decisionId`, reason, `disposition:MAPPED|NONNORMATIVE`, draft/reviewer proposition IDs, current IDs, and exact `currentAtomicScopeSha256` map. Real semantic differences must actually be reviewed; valid structure is not an independent semantic oracle.

Entries carry the agreed `entryKind:ATOMIC_OBLIGATION|SOURCE_CONTEXT`, source identity, and atomic scope when applicable. Atomic scope is exactly `{key,statement,sourceSpans,contextSourceLocations,sha256}`. Its hash uses `closed-loop-canonical-json/1` over the first four fields. Source spans are ordered absolute UTF-8 half-open offsets within the primary raw line, without LF, with exact text and raw byte hash. Context line hashes also use raw bytes without LF; `controllingText` uses the exact trimmed line. Duplicate IDs, keys, scopes, malformed offsets, UTF-8 splits, incorrect section anchors, stale context and missing reverse memberships fail closed. Coverage is the sorted, deduplicated union of all primary and context links for the line.

Fresh atoms have `birthIdentity:{sourceSha256,sourceAnchor:{line,lineSha256},atomicKey}` and ID `NREQ-` plus its canonical hash's first 32 hex characters. Historical IDs need an explicit crosswalk. The crosswalk covers every pinned predecessor ID exactly once and enforces agreed cardinalities. Old compound IDs cannot remain active as narrower children or extra counted ancestors. Legacy singleton retention needs a distinct decision with `priorWasSingleObligation:true`; merging requires `equivalenceReason` and preservation of source anchors. Removal requires `removalAuthority` and absent controlling text. Same-target mappings are allowed only as explicitly reconciled equivalent merges.

When predecessor source differs, reconciliation also pins `sourceTraceManifest` (historical current-source line trace) and `historicalSourceRelocationCrosswalk` (existing accepted `closed-loop-source-relocation-crosswalk/1`). They are explicit inputs. Raw relocation/trace identity is checked, never treated as semantic equivalence or proof renewal. Every current reviewed source-trace line must remain active as a primary or context anchor. These archived artifacts are provenance; `requirements[]` remains the sole active universe.

`SOURCE_CONTEXT.contextClassification` contains classification `STRUCTURAL_REQUIREMENT_CONTEXT|HISTORICAL_NONNORMATIVE_CONTEXT`, reason and governing IDs. Structural context also requires ordered `governingSourceRanges`; membership includes every atomic primary entry within those ranges and every governed atom must carry the context anchor. Both authored passes must independently classify context before its exclusion from the behavioral denominator.

Generation supplies only candidate owner/test defaults from source traces; it never inherits parent proof. Atomic requirement evidence bindings and assertion bindings need `atomicObligationSha256`. Full coverage additionally carries the exact `reviewedAtomicStatement`, `sourceSpans`, `contextSourceLocations`, and scope digest. Its independent coverage-review record binds the same digest, statement and context, besides all existing declaration/input/owner/receipt checks. Legacy full-line proof remains unchanged. Atomic proof source annotations must belong to this atom's exact spans; a source-line hash alone cannot bind siblings. All atomic source/reconciliation/predecessor inputs enter receipt fingerprints.

## Changed singleton scope after controlling-source replacement

`CHANGED_SINGLETON_SCOPE` represents one reviewed predecessor obligation whose primary bytes remain but whose semantic scope changed through added, removed or replaced context. It maps exactly one fresh atomic ID and retires the old ID; it cannot be labeled UNCHANGED_ATOMIC, SPLIT_COMPOUND or MERGED_EQUIVALENT, and it never inherits predecessor proof. The observed motivating case is deletion of historical §32.4A: 23 Stage08–30 operation-list source lines retain identical primary bytes while losing the prior conditional operation-set extension. Historical bytes and identities remain archived. This support does not itself accept the reconciler’s individual scope decisions.

A changed-singleton decision requires `priorWasSingleObligation:true` and `scopeChange` with `priorNormativeRequirementId`, `currentNormativeRequirementId`, reviewed `priorStatement`, exact `currentStatement`, `currentAtomicObligationSha256`, and reason. Its authority is `{kind:"CONTROLLING_SOURCE_REPLACEMENT",priorSpecificationSha256,currentSpecificationSha256,reason}`; both exact source identities must match and differ. Full `priorContextSourceLocations` and exact `currentContextSourceLocations` are required. `contextChanges` exactly accounts for their content differences, with kinds REMOVED, ADDED, or REPLACED, applicable `priorContextSourceLocation`/`currentContextSourceLocation` and a reason. Repeated, missing, stale, invented or unresolved context changes are rejected. A merely relocated context is not a semantic change. Removed context text must actually be absent from the current source.

Reconciliation additionally pins `priorSpecificationSource:{path,sha256}` as an explicit input for changed-singleton validation. The file is an exact archived UTF-8 `.txt` source under `verification/` or `specification/`, and its digest must equal the predecessor manifest’s specification digest. This permits validating historical context lines that were not primary rows in the old line-level manifest, including actual old §32.4A lines2872/2874. Loader and receipt fingerprints include these immutable historical bytes under the same containment policy. They are provenance, never a second active specification.

The focused regression retains the exact old crosswalk validator to demonstrate its unsupported-relation failure, then checks the repaired relation plus counterfeit labels, stale authority/scope/context, missing old source, old-ID reuse, extra children, active ancestors, copied proof, and unresolved/duplicate context differences.

### Cross-source equivalence and duplicate convergence hardening

An absent `scopeChange` never defaults a legacy row to unchanged semantics. Across source digests, UNCHANGED_ATOMIC and MERGED_EQUIVALENT require one explicit `decision.scopeEquivalences[]` record per prior ID: old/current IDs, old/current specification digests, reviewed prior/current statements, target atomic scope digest, complete old/current context locations, and reason. These scoped records must preserve context content; recorded historical atomic/clarification context is mandatory independently of those declarations. Archived historical primary anchors are also checked whenever historical bytes are available. This validates actual reviewed evidence and source bindings, not an automatic semantic-language oracle.

Explicitly reviewed duplicate historical predicates can both change into one fresh atom. Every such CHANGED_SINGLETON_SCOPE decision must carry an identical `changedDuplicateGroup` with nonempty `groupId` and `priorEquivalenceReason`, exact target ID, sorted complete `priorNormativeRequirementIds`, and `scopeChangeSha256ByPriorId` binding every separately validated change record. Missing/stale groups, missing members, mixed relationship types and unreviewed convergence fail. The motivating duplicate occurrences are the §14.6 and §37 operation predicates; duplicate active atoms are not introduced.

## Reviewed component convergence

A `SPLIT_COMPOUND` ancestor can share one reviewed equivalent child with another historical occurrence while retaining its truthful split relation. Each incoming decision carries exhaustive `componentPartitions` for its old IDs: exact old source identity/primary anchor, `complete:true`, reason, and one component per current target with old UTF-8 spans, old/current context inventory, prior statement, target atomic digest, and explicit equivalent-component reason. Identical `componentConvergenceGroups` bind the complete incoming old-ID set and each selected component's canonical digest. `EQUIVALENT_COMPONENTS` requires mixed split/equivalent relations, fresh targets, and no inherited proof.

`COMPONENT_OF_CONTRACT` retires a historical component ID without pretending the fragment equals the entire closed contract. Its `CONTRACT_COMPONENTS` group carries explicit containment review, source spans and all applicable targets; a genuinely reviewed whole-contract ID can remain. One shared operand/condition can qualify several distinct contracts, with complete per-target groups and one exhaustive old-ID partition. It is not minted as several independent obligations. All source contexts and old primary spans are checked against exact historical bytes, all active scope digests must match, and copied proof is rejected. Existing ordinary merges, changed-singleton groups and unsupported convergence guards remain separate.

The focused synthetic suite executes the frozen pre-correction crosswalk against a genuine mixed split/merge-shaped fixture (rejected before, accepted with complete scoped evidence), tests an explicitly contained component and shared condition across two contracts, and rejects stale/partial partitions, missing incoming members/groups, false equivalence, wrong source spans, scope hashes, missing reasons, retained component IDs and inherited proof.

A single genuine candidate-reconciliation decision may carry `scopeChanges[]`, keyed by historical ID, for equivalent changed-singleton occurrences. The old singular `scopeChange` remains supported, but the two forms cannot coexist. Each predecessor resolves exactly one independently validated scope change, and changed-duplicate group hashes select that predecessor's own record. Missing, duplicate, ambiguous or unrelated changes fail closed.
